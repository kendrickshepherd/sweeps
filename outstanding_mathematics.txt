Outstanding Mathematics - Claims Requiring Formal Proof
=======================================================
Branch: piola_dev
Created: 2026-10-01
Revised: 2026-10-05 (review corrections; see REVISION LOG at the end)
Companion to: outstanding_issues.txt (engineering work items)

PURPOSE.  outstanding_issues.txt tracks what to BUILD.  This file tracks what is
BELIEVED but not PROVED.  Several conclusions in that file are load-bearing -
production code is shaped by them and tests are labelled PERMANENT on their
authority - yet their evidence is a code-reading argument or a finite set of
fixtures, not a proof.  Conflating those with measured exhaustion has already
caused one inverted attribution (see outstanding_issues.txt, "CORRECTED" at the
head of the merge-pairing entry), so the distinction is recorded explicitly.

PROVENANCE.  This file is committed BEFORE the Row D diagnostics are run.  That
ordering is deliberate: the hypotheses and their closure language are fixed in
the record before any measurement exists to tempt a broader claim.  Do not
revise an item's CLAIM text to match a later result; add the result and change
the class.

EVIDENCE CLASSES.  Every item below carries one.  Do not promote an item to a
stronger class without the work named in its ENOUGH WOULD BE field.

  EXHAUSTIVELY VERIFIED  the claim ranges over a finite input space and every
                        member was executed.  A complete case analysis of
                        "the implementation agrees with the restated rule on
                        these inputs" - stronger than MEASURED, because the
                        domain really is covered.  NOT a derivation: the oracle
                        is a hand-rolled restatement, the test is itself
                        executable code that can be wrong, and whatever is not
                        in the enumerated domain is not covered.
  MEASURED             true on specific fixtures.  Says nothing about
                        configurations no fixture exercises.
  ARGUED-FROM-CODE     follows from reading the implementation.  Sound only
                        while that code is unchanged, and only if the reading
                        covered every path.
  DEFINITIONAL         holds by the construction of the object, not by
                        validation.  Lapses only if the construction changes.
  ASSERTED             stated as standard or obvious; no derivation recorded
                        here and none located in the repository.

PRECEDENT for this discipline, already in outstanding_issues.txt: the CAUTION
that onSameVertex reads the same phi under examination, so merge/vertex
agreement is tautological and is NOT evidence.  That is the failure mode this
file exists to catch earlier.

A STANDING DISTINCTION, load-bearing in M1, M3 and M4.  Two different things
are easy to conflate:
  CONTINUOUS CONFORMITY - which continuity conditions the function space
    requires.  Settled by analysis; see M3.
  IMPLEMENTATION COVERAGE - whether this code's iterators actually reach every
    discrete basis function the condition applies to.  NOT settled by any
    analytic argument, however correct.  Only per-face, per-DOF assertions
    establish coverage.
An argument about the first is routinely mistaken for evidence about the second.

M1. TRANSITIVITY OF FACE-LEVEL MERGING TO LOWER-DIMENSIONAL CELLS
-------------------------------------------------------------------------------
  CLASS     ARGUED-FROM-CODE.  This is the headline unproved claim.
  SITE      src/basis/VectorConformingMultiPatchSplineSpace.cpp:64
            (cell_dim = multi_cmap.dim() - 1), versus the scalar merge's
            cell_dim = 0 .. param_dim-1 at MultiPatchSplineSpace.cpp:278.
  CLAIM     Merging DOFs only on dim-1 faces, combined with oriented union-find
            transitivity, correctly identifies every shared DOF on cells of
            lower dimension - in particular 3D H(curl) tangential DOFs on an
            edge shared by several patches.
  ARGUMENT  (sharpened 2026-10-05)
            1. H(curl) conformity in 3D requires matching tangential traces
               across codimension-one faces, and imposes no separate
               codimension-two continuity condition.  (M3.)
            2. If every incident patch copy of an edge is connected through
               face gluings CONTAINING THAT EDGE, pairwise tangential-trace
               identification propagates transitively through the edge's
               incident-patch graph.
            3. Path independence requires trivial orientation parity around
               every cycle of that graph.  (M4.)
            The qualifier in 2 is load-bearing: the chain must run through faces
            incident to the edge, i.e. within the edge's incident-patch graph,
            NOT along an arbitrary path in the patch graph.  An earlier draft
            said only "a chain of face gluings", which is loose enough to be
            unfalsifiable.
  NOT PROVED  (a) Step 2's hypothesis - that every incident patch copy is so
            connected - is exactly what the fixtures must check.  The theory
            supplies the reduction; it does not supply the hypothesis.
            (b) IMPLEMENTATION COVERAGE.  Even granting steps 1-3, nothing above
            shows that this implementation's face iterator enumerates every
            discrete basis function with nonzero trace on the face.  That is a
            property of cornerCells and the tensor-product iteration, not of the
            function space, and it must stay supported by per-face DOF
            assertions rather than by the analytic argument.
            (c) That the parity carried along a chain composes to the CORRECT
            value, not merely a consistent one - see M4 and M5.
  ENOUGH WOULD BE  An argument over the edge's incident-patch graph: for a
            shared cell c of dimension k < dim-1, show that the set of
            (patch, local-DOF) pairs supported on c is a single connected
            component of the graph whose edges are the declared face gluings
            incident to c, and that the induced parity is the one the de Rham
            conformity condition requires.  Fixtures cannot supply this; they
            can only refute it.
  CLOSURE LANGUAGE  Until proved, state results in this form and no stronger:
            "Face-level merging with oriented union-find transitivity correctly
            merges the tested 3D H(curl) edge classes for cyclic and
            valence-three face-connected configurations supported by the current
            API."  Do NOT write "proves transitivity for everything
            expressible" - that conflates fixture evidence with a theorem and
            additionally smuggles in M2.

M3. NO INDEPENDENT CODIMENSION-TWO CONFORMITY CONDITION
-------------------------------------------------------------------------------
  CLASS     ASSERTED as to the analysis; the analytic content is standard and
            was accepted by review 2026-10-05, but no derivation is recorded in
            this repository.
  CLAIM     H(curl) conformity in 3D requires matching TANGENTIAL traces across
            codimension-one faces; H(div) requires matching NORMAL traces across
            codimension-one faces.  Neither imposes an independent continuity
            condition on codimension-two cells (edges).  Hence row D's
            "CORRECT for H(div)" verdict on the dim-1 restriction.
  SETTLED   The absence of an independent codimension-two condition.  This is
            what the continuous-space argument does establish.
  NOT SETTLED BY THAT ARGUMENT  IMPLEMENTATION COVERAGE, per the standing
            distinction above.  The analytic fact says which continuity is

            enumerates every discrete basis function with nonzero trace on a

            which DOFs the per-face merge REACHES.  Coverage stays supported by
            the per-face DOF assertions, not by analysis.
  ENOUGH WOULD BE  Half a page: name the conformity condition, name the DOF set
            with nonzero trace on a given face, and show the union of the
            per-face merges covers it.  The same half page settles the H(curl)
            analogue's exact failure mode.

M4. THE ORIENTATION PARITY IS A COBOUNDARY, AND THE COMPUTED ONE IS CORRECT
-------------------------------------------------------------------------------
  CLASS     mixed.  The algebraic characterisation is PROVED (below).  That the
            union-find's test is complete on the graph SUPPLIED TO IT is
            ARGUED-FROM-CODE and verified.  That the supplied graph equals the
            intended graph is NOT established by any current evidence.  That the
            computed parity VALUE is correct is M5.
  SITE      src/util/UnionFind.hpp (unite); coordinateTransform at
            src/param/ParametricAtlas.cpp:120.

  ALGEBRAIC STATEMENT (corrected 2026-10-05).  Let G be the graph whose vertices
  are the patch-local copies of a shared cell's DOFs and whose edges are the
  declared face gluings relating them.  The aligned flag is a Z_2-valued
  1-COCHAIN c on G.
    - Calling consistency "a cocycle condition" is VACUOUS and was wrong in the
      2026-10-01 draft: G is a 1-dimensional CW complex, so C^2(G) = 0, the
      coboundary out of C^1 is the zero map, and EVERY 1-cochain is a cocycle.
    - The correct condition is that c be EXACT - a COBOUNDARY.  Consistency
      holds iff there is f : V -> Z_2 with c(uv) = f(u) + f(v), i.e. c = df,
      i.e. [c] = 0 in H^1(G; Z_2).  Since H^1(G; Z_2) = Hom(H_1(G), Z_2), the
      class is detected by parity sums around cycles.
    - f is a GAUGE: it is exactly the freedom to flip the sign convention of
      each patch's local DOFs.  Consistency is gauge-invariant; see M5 for why
      that matters.

  WHAT UnionFind ACTUALLY COMPUTES.  Spanning-tree gauge fixing.  find's path
  compression leaves is_opposite_parent as parity-to-root, which IS a choice of
  f (root = 0).  Tree edges DEFINE f; the root_a == root_b branch tests
  c(ab) against f(a) + f(b) and THROWS ("trying to unite two elements with
  inconsistent orientation") when they disagree.  So co-tree edges test df
  against c.  Co-tree edges generate the cycle space, hence:
    On the graph actually supplied to it, the union-find's test of [c] = 0 is
    COMPLETE - not a sampling of cycles.

  THE NARROWING THAT MATTERS (review, 2026-10-05).  Completeness is relative to
  the SUPPLIED graph, and FINAL EQUIVALENCE-CLASS DATA DOES NOT ESTABLISH THAT
  THE SUPPLIED GRAPH IS THE INTENDED ONE.  If one face constraint is skipped,
  the remaining paths may still merge every patch-local ID into a single set:
  the final ID union looks correct while the missing co-tree edge - and
  therefore its parity check - was never exercised.  A merge never attempted is
  an edge absent from G, shrinking the tested cycle space silently.  So neither
  a correct central-edge ID count nor a construction that fails to throw is
  evidence that the intended constraints were all applied.

  REQUIRED EVIDENCE.  A fixture must assert every INTENDED constraint, not only
  the final equivalence class:
    1. the connection map contains twice the declared face-pair count (M9);
    2. every intended face adjacency contains the selected global edge;
    3. for every relevant local H(curl) DOF pair across every declared face,
       the global IDs agree;
    4. their orientation relationship matches the INDEPENDENT expected sign
       (M5);
    5. the incident-patch graph is connected and has beta_1 > 0;
    6. at least one tested cycle contains a nontrivial orientation transition.
  Only with 1-6 in place do final central-edge set equality and successful
  construction become meaningful SUMMARY checks.

  COROLLARY, why chain fixtures prove nothing here.  On a tree every 1-cochain
  is a coboundary, so consistency is automatic and the parity test is vacuous.
  That is the algebraic reason the existing L-shaped three-patch case passes
  without bearing on this question, and why condition 5 above is mandatory.

  STATUS 2026-10-06, test/RowD_Diagnostics_test.cpp step 5.  Assertions 1, 2
  and 5 are MEASURED on two fixtures; 3, 4 and 6 need the function-id merge and
  remain open.
    FIXTURE A, the four-patch 3d case already in MultiPatchSplineSpace_test.cpp
    at line 325.  Its topology was measured, not assumed - it is declared by
    DART PAIRS, so the glued sides cannot be read off the source and had to be
    recovered from the normalized connections() map.  It is K4: four
    single-element hexes, each glued to all three others on exactly three of
    its six faces.  Edge shapes: 12 single-patch, 12 two-patch (beta_1 = 0,
    trees, NON-discriminating), and 4 three-patch edges with 3 arcs, connected,
    BETA_1 = 1 - one per patch triple of K4.  So assertion 5 is SATISFIED and
    the fixture does exercise the parity test.  Assertion 1 holds: 6 declared
    pairs give 12 entries, so no emplace drop (M9).  Assertion 2 holds in the
    strong form - the union of arcs over the four cyclic edges is exactly the
    set of 6 declared pairs, so no declaration goes unexercised.
    FIXTURE B, a swept three-patch ring, built here to exercise the OTHER
    producer: three quads fanned around a shared corner, glued i:side0 to
    i+1:side2 so the ring closes, then passed through
    connectionsOfSweptMultipatch.  6 connections in, 6 swept, 6 realized - the
    sweep loses nothing.  Exactly 1 cyclic edge, the swept central vertex: 3
    patches, 3 arcs, connected, beta_1 = 1.  Assertion 5 SATISFIED.
    TOPOLOGY-ORBIT ACCOUNTING, both fixtures.  The local-edge total must equal
    the global total plus the identifications.  A: 4 x 12 = 48 = 28 + 20.  B:
    3 x 12 = 36 = 25 + 11.  Both exact, and both asserted.  This is NOT an
    independent merge oracle: cellCount and the orbit walk run on the same
    combinatorial-map machinery, so it cannot corroborate the function-id
    merge.  What it does establish is that the observed global edge orbits
    account for every patch-local edge with no unexpected same-patch
    multiplicity.
    PRECONDITION, asserted per fixture.  The incident-patch graph is read off
    PATCH PAIRS, which is faithful only while at most one declared interface
    joins any ordered patch pair; with two, distinct faces would collapse into
    a single arc and the graph would understate beta_1.
    maxInterfacesPerPatchPair == 1 is asserted on both fixtures, and every
    cyclic edge additionally asserts that its arcs resolve one-to-one onto
    declared interfaces.  Step 6 carries ConstituentSide identity explicitly
    and must not rely on this precondition.
    NOT YET ASSERTION 6.  Two of fixture A's four cycles traverse a ZeroToOne
    permutation and fixture B's are all ZeroToZero, but a PERMUTATION IS NOT AN
    ORIENTATION SIGN: the aligned flag fed to UnionFind is derived from dart
    geometry through F_b o P o F_a, not from P alone.  Assertion 6 is therefore
    a step 6 item, measurable without geometry once functionIdMap() is
    populated.

M5. coordinateTransform IS "CORRECT BY CONSTRUCTION"
-------------------------------------------------------------------------------
  CLASS     ARGUED-FROM-CODE, now split by coordinate block (2026-10-05).
  SITE      src/param/ParametricAtlas.cpp:94-160 (getFrame, coordinateTransform).
  CLAIM     It derives the component map and sign from getFrame on both sides by
            comparing actual parent-point coordinate changes, never reading the
            permutation enum, so it is correct by construction and is not
            implicated in the side-blindness defect class.
  WHY IT IS PERSUASIVE  The reasoning is sound as far as it goes, and probe 2
            measured the expected swap for the rotated gluing.  The
            enum-blindness really does immunise it against the Stage 1 defect.

  WHY CONSISTENCY IS NOT CORRECTNESS.  By M4, the union-find test is invariant
  under c -> c + df.  A COHERENTLY wrong sign convention is a gauge
  transformation and is therefore STRUCTURALLY INVISIBLE to it.  No amount of
  construction-not-throwing can detect one.  An independently derived expected
  orientation is mandatory, not optional.

  THE INDEPENDENT COMPARISON, AND ITS EXACT REACH.  sideCoordinateTransform
  derives the signed axis permutation from (dim, source_side_id,
  destination_side_id, permutation) and NEVER CALLS phi; coordinateTransform
  derives it from getFrame corner geometry THROUGH phi.  Comparing them on the
  same interface is a genuine cross-derivation, not a restatement.
    REACH (narrowed by review 2026-10-05): SideCoordinateTransform describes
    only the dim-1 TANGENTIAL coordinates, whereas coordinateTransform includes
    the NORMAL coordinate.  So exhaustive agreement can derive and verify the
    tangential block only.  The supported claim is:
      "The independent transform comparison derives and exhaustively verifies
      the tangential component mapping and sign convention used by 3D H(curl)."
    It CANNOT derive the whole factor = ( coord != dim - 1 ) expression, and in
    particular not its normal branch.
  REMAINING SOFT SPOTS
            (a) NOT INDEPENDENT OF phi.  getFrame calls phi to reach every
            corner.  So coordinateTransform corroborates phi only in the weak
            sense that two consumers of phi agree; it is NOT an oracle for phi,
            and the standing description of phi as "the independent oracle" must
            not be read as independence from this function.  Same tautology as
            the onSameVertex CAUTION, one level up.  PARTIALLY ANSWERED by the
            comparison above, which is phi-free on one side - for the tangential
            block only.
            (b) find_change returns the FIRST coordinate differing by more than
            1e-10 and throws if none does.  Well-definedness requires exactly
            one coordinate to differ between a frame corner and the frame
            origin.  True for axis-aligned tensor-product parent domains; not
            established in general, and silent (first wins) rather than
            diagnostic if two differ.
            (c) THE NORMAL BRANCH OF factor = ( coord != dim - 1 ) STAYS OPEN.
            The term is an unexplained convention with no derivation in code or
            notes, and it is load-bearing for every sign the vector merge
            produces.  The tangential comparison does not reach it.  H(div)
            depends on the normal branch, so M5 may NOT be closed on H(curl)
            evidence.
  ENOUGH WOULD BE  For the tangential block: the comparison above over the 144
            discrete interface classes, with the index-base and direction
            conventions reconciled by honest derivation rather than fitted - a
            fitted reconciliation merely re-expresses one convention in the
            other's vocabulary and proves nothing.  For the normal branch: its
            own derivation, or an independent expected-orientation oracle for
            H(div) normal traces.  Plus a property test asserting exactly one
            coordinate changes between frame origin and each frame corner.

M10. THE PER-ELEMENT SHARED COUNT OF 2
-------------------------------------------------------------------------------
  CLASS     MEASURED 2026-10-05.  The conjecture below was committed at 8d1e4ce
            BEFORE the sweep ran; the measurement confirms it.
  CLAIM     The H(div)/H(curl) per-paired-element shared count of 2 in 2D is the
            correct degree-dependent trace count, not a symptom of a defect.
  CONJECTURE (as written before measuring)  For a degree-p 2D de Rham pair the
            interface-tangential component carries degree p-1, giving p
            functions per element; so the count should track 2 -> 3 -> 4 for
            p = 2, 3, 4.
  RESULT    EXPERIMENT 1, test/RowD_Diagnostics_test.cpp, degrees 2/3/4 on both
            orientation classes - sides 0<->1 (non-reversing) and sides 0<->3
            (reversing), two interface elements each:

              space    trace fns/elem     shared/elem
              H1       p+1                p+1
              H(div)   2p+1               p
              H(curl)  2p+1               p

            shared = p exactly: 2, 3, 4 for p = 2, 3, 4, IDENTICAL on both
            orientation classes.  The conjecture is confirmed, and the count is
            not tied to one class.  The 2p+1 trace total decomposes as
            p + (p+1): the conforming component carries degree p-1 (p functions
            per element, all shared) and the other carries degree p (p+1
            functions, correctly NOT shared).  So the relation is a dimension
            count, not a curve fit through three points.  The p=2
            non-reversing row reproduces the committed Phase 0 numbers exactly
            (rows 5, cols 5, shared 2, identity column match 2), so the new
            harness agrees with the old one where they overlap.
  WHAT THIS CLOSES  shared == 2 is no longer evidence of a defect, which
            retires it as row D's live marker (outstanding_issues.txt criterion
            8).  Row D then has NO live marker in the Phase 0 suite.
  WHAT THIS DOES NOT CLOSE  Everything row D is actually about.  This is a
            codimension-ONE face interface in 2D.  It says nothing about 3D
            codimension-TWO edge classes, which remain the open question and
            still need the M4 fixture assertions.  Promoting the TEMPORARY label
            is justified by this measurement alone, but closing row D is not.

  SIDE RESULT, UNPLANNED - THE ORIENTATION BOOL IS MEASURABLY ACTIVE, AND ITS
  OBSERVED SIGN IS CONSISTENT WITH THE EXPECTED DE RHAM ORIENTATION.
            For every degree and every interface element, every shared
            extraction row agrees under the expected ordering and sign, and
            under that same ordering the opposite-sign comparison matches
            nothing:

              space    non-reversing 0<->1   reversing 0<->3
              H1       +identity             +reversed
              H(div)   +identity             +reversed
              H(curl)  +identity             -reversed   <-- negated

            H(curl) across a reversing interface agrees after BOTH reversing
            the column order AND negating, to 1e-10, with nothing matching in
            the non-negated reversed channel.  That is consistent with the
            expected de Rham orientation: the conforming component of H(curl)
            in 2D is the tangential one, the induced tangent directions of the
            two patches are antiparallel across a reversing pair, so the two
            orientation bools must differ for the global function to be
            single-valued - and the minus must appear exactly once, which
            ra + rb.reverse() == 0 confirms.  H(div)'s conforming component is
            the normal and needs no flip.
  WHAT IS NOT CLAIMED  That only one of the four comparisons ever matches.
            Incidental partial agreement under a DIFFERENT ordering does occur
            and is expected: a symmetric scalar basis function is its own
            mirror, so non-reversing H1 shows 1 reversed match and reversing H1
            shows 1 identity match at p = 2 and p = 4, and 0 at p = 3 where
            p+1 is even and there is no central function.  The test therefore
            asserts that the expected channel matches every shared row and its
            opposite-sign counterpart matches none; it deliberately does NOT
            assert that the other two comparisons vanish.  For H(div) and
            H(curl) they do happen to vanish throughout this sweep, but that
            stronger property is neither pinned by the test nor required for
            correctness.

    evidence is closed narrowly, and should say so.

    equivalence class (M4).
