HEADLINE: PHASE 0'S ATTRIBUTION IS INVERTED.  Phase 0 recorded that "Flip1d
reversal is AUTHORITATIVE ... the function-ID merge is the one inconsistent
component."  That is wrong.  The topology (phi) and BOTH function-ID merges are

WHY THE TOPOLOGY IS CORRECT

  1. phi's cross-interface pairing is an orientation-consistent involution
     (probe 5).  For every interface dart, in both a parity-identity gluing
     (sides 0<->1) and a parity-reversed one (sides 0<->3):
         phi_2(phi_2(d)) == d                   (involution)
         onSameVertex(d, phi_2(d))        == 0
         onSameVertex(phi_1(d), phi_2(d)) == 1
     The last value is the decisive signature: phi_2(d) begins at the HEAD of
     d, i.e. the same edge traversed in the opposite direction.  That is what a
     consistently oriented map requires of two faces sharing an edge.

  2. The convention is uniform with the patch interior (probe 4).
     onSameVertex(d, phi_2(d)) is false for all 24 patch-INTERIOR edges as well
     as all 3 interface edges, in both gluings.  The interior path is
     TPCombinatorialMap, which is not under suspicion, so "phi_i shifts the
     originating vertex" is the repository's own convention and the interface
     crossing obeys it.  The scalar merge's reverse = not onSameVertex(...) and
     the vector merge's constexpr reverse = true are therefore both right, and
     no double reversal exists.

  3. The reference paper agrees.  arXiv:2608.29545 describes inter-patch phi_n
     as exactly the implemented drop-permute-raise, states that "the phi_i
     operator shifts both the originating vertex and the i-dimensional cell ...
     while leaving all other cells constant", that adjacent cells traverse
     their shared boundary in opposite directions, and that there is "only one
     permutation in the 1d side of a 2d patch".  That last point vindicates the
     hardcoded Flip1d at MultiPatchCombinatorialMap.cpp:215-216: in 2D the
     stored permutation carries NO information, so no consumer can derive the
     correspondence from it alone.

  CAUTION for future work: onSameVertex (CombinatorialMapMethods.cpp:481) is a
  LocalCellMarker over Vertex orbits, i.e. it reads the same phi under
  examination.  Merge/vertex agreement is tautological and is NOT evidence.  An
  earlier draft of this investigation briefly treated it as an oracle.

THE ACTUAL DEFECT: SIDE-BLIND CONSUMERS

  flipNecessaryDarts (MultiPatchCombinatorialMap.cpp:35-58) is applied twice per
  crossing, in dropToBoundary:137 and in raiseFromBoundary:174.  Its input is
  unflattenFull(...).unflat_darts, i.e. an already-PARAMETRIC element index, so
  it converts parametric index into index along the induced (CCW) boundary
  traversal.  In 2D it flips boundaries 1 and 2, exactly the two whose CCW
  traversal opposes increasing parameter; the dart tables at :27-29 give the CCW
  order local darts 0,1,2,3 -> bdry 3,0,2,1 -> bottom, right, top, left.

  So phi computes  F_b o P o F_a  in parametric index space, where F_s is the
  per-side canonicalization and P is permuteAcrossBoundary.  Every trace-side
  consumer computes P alone.

  2D RULE (probes 1, 3 and 6; probe 3 covers all 16 ordered side pairs).
    phi reverses the parametric element index iff
        [a in {1,2}] + [b in {1,2}]  is EVEN.
    permuteTraceSideIndex reverses unconditionally.  They agree on 8 of the 16
    ordered pairs and disagree on the other 8:
      AGREE     0<->0  0<->3  1<->1  1<->2  2<->1  2<->2  3<->0  3<->3
      DISAGREE  0<->1  0<->2  1<->0  1<->3  2<->0  2<->3  3<->1  3<->2
    Corrected 2D transform: reverse iff [a in {1,2}] + [b in {1,2}] is even,
    equivalently aligned = ([a in {1,2}] + [b in {1,2}]) is odd.

  3D RULE (originally probe 7, 120 gluings through the PRODUCTION dart-pair
  constructor so permutations were DERIVED by initializeInterMapConnections;
  now measured EXHAUSTIVELY over all 144 triples by the registered test).
    permuteTraceSideIndex's four 3D cases are character-for-character identical
    to permuteAcrossBoundary's, so the trace reproduces the permute step exactly
    and omits precisely the two flipNecessaryDarts applications.  With F_s =
    flip tangential axis 0 iff s in {0,3,4} - the 3D branch's set, which DIFFERS
    from 2D's {1,2} - agreement holds iff F_b o P o F_a == P:

WHY NO EXISTING TEST CAUGHT IT - THREE INDEPENDENT MASKING MECHANISMS

  1. Palindromic interface knot vectors (Phase 0's finding).  Identity and
     reversed merges coincide.
  2. Count invariance.  numFunctions is the SAME under both conventions in every
     configuration measured: probe 3 reports 45 from raw 50 for all 16 2D side
     pairs; probe 1 reports 25 for the agreeing and the disagreeing gluing
     alike.  No count-based assertion can EVER discriminate.  The visible
     symptom is per-paired-element shared sets: with 5 tangential functions a
     reversal fixes only the middle index, so a wrong-convention merge still
     merges 5 functions while sharing only 1 per paired element (surviving id
     10, the middle).
  3. test_c0 evaluates at the reversal's FIXED POINT.  Both the scalar
     (MultiPatchSplineSpace_test.cpp:15-70) and vector
     (VectorConformingMultiPatchSplineSpace_test.cpp:36-101) helpers derive each
     side's parent point from pointOnBoundary(cubeDomain(dim),
     parentDomainBoundary(atlas, side_e)).  ParentPoint.cpp:48 sets each
     non-zero coordinate to 1/num_group_nonzero_coords, which is 0.5 along an
     edge's free axis.  Probe 5 measured the point as [1, 0.5] in all six cases:
     the edge MIDPOINT, where identity and reversed correspondence agree
     exactly.  Both helpers also locate the other side with
     phi(cmap, cmap.dim(), d) and compare only connectivity entries the merge
     already declared shared, so they are self-consistent with whatever phi and
     the merge jointly do.
  Additionally the vector tests assemble geometry through
  multiPatchCoefficients(geom_ss, ...), i.e. through the merge itself, so they
  can be self-consistent without being independently correct.

  CONSEQUENCE: the vector shared_ids == 0 recorded in Phase 0 is EXPLAINED, not
  a helper bug.  The H(div) normal component has an EVEN number of tangential
  functions, whose reversal has no fixed point; 0 is the even-length analogue of

         has identity axes.  A free function embeds a point.  Boundary and
         same-level interior records get the whole-side embedding.
       Why a full signed permutation per side, not a box plus
         iface.permutation: each side is self-contained, and no consumer
         composes the affine part with sideCoordinateTransform by hand,
         where permute-then-scale against scale-then-permute is the error.
       Enumeration, downward traversal (approved choice 1).  Per connection
         with first < second, for each level-0 cell on the first side,
         pair it with the second side's cell by the level-0 transform.  At
         each level note the first leaf met on each side (sideLeafIndices);
         when both sides have one, emit a record whose fragment is the
         current level cell; otherwise descend the first side's children on
         the side (iterateChildren) and pair each by that level's
         transform.  Leaves partition each patch, so this terminates;
         reaching the finest level without both leaves throws (DEFENSIVE).
       Embeddings from actual intervals.  Per tangential axis, offset =
         (fragment start - leaf start) / leaf length and scale = fragment
         length / leaf length, from each level's MultiPatchParametric-
         Atlas, always within one patch.  The only cross-patch step is the
         fragment-level signed permutation, the cell-wise affine
         correspondence that today's same-level pairing already assumes.
         Never from refinement ratios: the non-dyadic layouts discriminate
         (index ratio gives offsets 0 and 1/2, intervals give 0 and 1/3).
       Guard (DEFENSIVE): throw if a fragment box leaves its leaf box,
         beyond tolerance.  See OPEN GAP (child relation) below.

     Method (sampleLeaves, chainOutcome).  Each space of a chain is
       sampled on every leaf at the 3^dim grid {0.13, 0.47, 0.86}, in the
       patch's parametric coordinates, with first derivatives with respect
       to them.  A sample is keyed by patch and parametric point.  The
       spaces of a chain must share the keys, and two leaves may not share
       one.  For space k, A_k holds the samples, dA_k the samples of the
       image under d_k, and G_k = A_k^T A_k (sparse, then a dense LDLT):
         D_k           G_k+1^-1 A_k+1^T dA_k, the normal-equations fit
         inclusion     max|A_k+1 D_k - dA_k| / max(max|dA_k|, 1)
         composition   max|D_k+1 D_k| / (max|D_k+1| max|D_k|), zero
                       over zero being zero (compositionResidual)
         independence  sqrt(lambda_min / lambda_max) of G_k
         rank_k        singular values of D_k (BDCSVD) above 1e-8 times
                       the largest, and zero for an empty or zero
                       spectrum (countRank); the kernel edge is the
                       largest relative value counted zero, the image
                       edge the smallest counted nonzero
         b_k           n_k - rank_k - rank_k-1
       ARGUED, not tested: the Piola maps commute with the differentials,
       so the parametric relations are the physical ones patch by patch.
       On each leaf every function and image is a polynomial of degree at
       most 2 per axis, which the grid determines.  So equal samples are
       equal functions, and A_k is injective iff the basis is independent.
       The grid avoids leaf boundaries; conformity across interfaces
       enters only through the spaces themselves (steps 7 and 8).

     DEFINITIONS (reference).
       Domains.  For a leaf set, Omega^0 is the domain and Omega^{l+1}
         the union of the level-l cells that are refined.  Leaves and
         domains determine each other; Omega^{l+1} is a union of level-l
         cells and lies in Omega^l.
       Marks.  A mark is a leaf cell, of any level and patch.  Refining
         it puts it in Omega^{l+1}; a mark on the finest level adds a
         level.
       Policy.  Here, a predicate P(leaf set) at every level, checked by
         Sweeps.  The closure C(leaf set, marks) is the caller's
         (StokesFlow, D1).  A closure should meet:
         r1  P holds on the output whenever the input satisfies P;
         r2  with no marks, an input satisfying P is returned unchanged;
         r3  the output depends on the marks and the cells only, never on
             patch numbering, dart ids or side orientation.
         Sweeps can check r1 from outside, by validating every output.
     OBSERVATIONS, ARGUED.  Reference for closures (the caller's) and for
       EM and MHD later (O4, O5); the validator relies on none of them.
       O1  P_k: for every l, Omega^{l+1} is a union of supports of level-l
           k-form functions (k = 0 is ST Assumption 2 over the chosen
           0-form family, k = n is Evans et al. Assumption 1).  Neither
           family is closed under intersection (1D, degree 1: the hat
           supports {2,3} and {3,4} meet in {3}, a union of none).  So a
           target domain has no least P_k superset in general, and no map
           of target domains that is extensive, monotone and idempotent
           has exactly the P_k domains as its fixed points: the fixed
           points of such a map are closed under intersection.
       O2  Coarser cascade.  A level-l support through a cell of Omega^l
           can leave Omega^l, so a closure that may use any support can
           force Omega^l to grow, and so on down to level 1.  Supports of
           ACTIVE level-l functions lie in Omega^l (THB activity), so a
           closure that uses only those never cascades.
       O3  Reach across patches.  Level-l 0-form supports of the glued
           space cross interfaces and junctions; the L2 space is
           discontinuous across patches, so its supports stay in one
           patch.  A 0-form closure can refine a neighbouring patch; an
           n-form closure cannot.  That is the AMR POLICY rule above (an
           explicit refinement-class rule), not an interface rule.
       O4  P_0 implies P_n over the full bases, at maximal smoothness with
           simple knots, if our L2 level basis is the degree-(p-1)
           B-spline basis on the same breakpoints: in 1D a degree-p
           support is the union of the two degree-(p-1) supports inside
           it, the first and last included, and tensor products of unions
           are unions.  The zero-trace 0-form supports are among the full
           ones, so ST's Assumption 2 implies P_n too.  Repeated knots are
           not covered.
       O5  The 0-form family depends on the boundary conditions.  The

10. Nonmatching Interface / Mortar Framework (Long Term)
    True asymmetric patch interface refinement where the two sides have different
    mesh structures (not just different leaf selections) requires mortar/Nitsche
    machinery: coarse-to-fine trace constraint matrices, Piola-aware trace
    transfer, and hierarchical truncation across patch interfaces. This is out of
    scope for the current strongly-conforming H(div)/H(curl) layer.


11. Python / API Exposure (Phase 6)
    NavierStokesMultiPatchDiscretization, NavierStokesHierarchicalMultiPatchDiscretization,
    buildL2MultiPatch, externalTraceDofs, interfaceTraceElements, and the new
    TraceMesh enumeration functions are not yet exposed in SplinesAPI.cpp.
    H(curl) spatial evaluation exists in C++ but likewise has no dedicated Python
    discretization/API path. Defer these bindings until the Phase 5B C++ layer and
    tests are stable.


12. Degree-Elevation and Knot-Insertion Scope
    Exact univariate and tensor-product transfer operators are implemented in C++.
    Tensor-product degree elevation is tested for surfaces and volumes, and nested
    knot insertion/refinement supports up to three tensor-product directions.

    Current high-level limitations:
      - globallyPElevate exposes only 2D tensor-product surfaces in Python.
      - globallyHRefine exposes uniform n-adic refinement only for 2D
        tensor-product surfaces in Python.
      - Arbitrary nested knot insertion is available through the C++ refinement
        operators but is not directly exposed as a Python transfer operation.
      - Multipatch and hierarchical p-elevation are not implemented as high-level
        operations.
      - Degree reduction, knot removal, cell merging, coarsening, and
        smoothing/roughing remain future Bezier-projection operations.

    These limitations do not affect the currently tested exact global transfer
    operations. Address them incrementally with the future Bezier-projection
    framework rather than by adding unrelated special cases to the existing API.

CURRENT CAPABILITY BOUNDARIES AND INTENTIONAL NON-GOALS
-------------------------------------------------------------------------------

A. Rational Analysis Spaces Are Intentionally Unsupported
   File(s): src/eval/SplineSpaceEvaluator.cpp  NURBSSpaceEvaluator

   The supported compatible-IGA formulation uses:
     - Polynomial B-spline differential-form spaces for the parametric H1,
       H(curl), H(div), and L2 de Rham sequence.
     - A B-spline or NURBS geometry map.
     - Pullbacks/Piola transformations to transport the polynomial analysis
       complex to the physical domain.

   NURBSSpaceEvaluator therefore implements manifold, Jacobian, Hessian, and
   parametric-to-spatial geometry evaluation. Its generic analysis-basis methods
   intentionally throw. This is a deliberate separation of geometry from
   analysis, not an unfinished prerequisite for the current de Rham framework.

   Compatible rational differential-form constructions do exist in the
   literature, including the Hiemstra-Huijsmans-Gerritsma partition-of-unity
   construction. That method derives weight-dependent rational edge, face, and
   volume functions; it is not obtained by merely evaluating the ordinary NURBS
   basis in every space. Supporting it would require a separate rational
   compatible-space family, derivative/incidence operators, refinement rules,
   and multipatch/hierarchical theory.

   Decision: A Hiemstra-like rational compatible analysis framework is not
   anticipated for sweeps. NURBS will remain a geometry representation, while
   compatible analysis will use polynomial B-spline spaces. Do not treat the
   intentionally throwing rational analysis methods as an outstanding defect.


B. Piola Evaluation Assumes Equal Parametric and Spatial Dimensions
   The implemented H1, H(curl), H(div), and L2 spatial values/first derivatives
   are tested for 2D planar domains and 3D volumetric domains, including curved
   geometry and nonuniform knot spans. They require a square
   parametric-to-spatial Jacobian.

   Embedded-manifold transforms, such as a two-dimensional analysis space mapped
   into three-dimensional space, are not supported by these routines. Physical
   normal/tangential trace values, side measures, and paired-interface
   evaluations are also not supplied by the volume evaluator; those belong to
   Phase 5B and the TraceSpaceEvaluator contract in items 8 and 9.


C. Strong Multipatch Coupling Uses Matching, Unscaled Interface Charts
   Current strong H1/H(curl)/H(div) merging supports compatible interface knot
   structure together with coordinate permutations, orientation reversals, and
   origin translations. Interface parameter scaling is rejected because the
   union-find DOF identification can represent equality and orientation signs,
   but not weighted constraints.

   Same-mesh asymmetric hierarchical leaf selection is the valid extension in
   item 1. Truly nonmatching interface meshes or scaled transition maps require
   the weak/mortar framework in item 10 and are not defects in the current strong
   coupling implementation.


D. Broken L2 Spaces Work; Physical Interior-Face Assembly Is Deferred
   Reducing a degree-p C0 H1 direction preserves interior multiplicity p while
   reducing the degree to p-1, producing C-1 L2 connectivity. This is supported
   within single patches and in multipatch/hierarchical constructions. The
   corresponding RT/Nedelec mixed primal/reduced continuity patterns are also
   supported.

   Element-local evaluation and algebraic broken-face enumeration work now.
   DG/Nitsche-style integration still requires Phase 5B physical trace evaluation;
   hierarchical coarse-fine interior faces additionally require the subdivision
   work in item 7.
